1. Describe the skip-list invariant. Explain why level 0 contains every key in sorted order and why a node promoted to level j must also appear in every lower level.
The invariant is the every level present should be sorted, level 0 should contain every node, and that nodes in higher levels must exist in every lower level. Level 0 must contain every key and in sorted order because it represents the original list and must remain intact in order for the upper levels to be structured correctly and for the list overall to be traversed in O(log n) time. A node promoted to level j must exist for every lower level because searches will need to traverse various levels in the list and when j is less than the target, will need to have the ability to traverse down to a lower level but stay at j. If j is missing on a lower level, this traversal will not be as effective and will error out rather than reaching the intended destination.

2. Explain why the search procedure returns the correct exact key, predecessor, or successor. Identify the point at which the algorithm knows it cannot move farther right on the current level.
The search procedure is looking for a specific key and will return the requested information based on its existence. This searching algorithm will move along a current level until there is no further right node OR the next key to the right will be smaller than the target key and when that happens, it will descend a level and keep looking. Once it has located the requested key, it will return it or the predecessor/successor so that it can be used elsewhere

3. Explain why insert and delete preserve sorted order and the multi-level representation, including the updates needed at every level containing the affected node.
Insert and delete must preserve sorted order in order for the searching algorithm to retain its O(log n) complexity, as searching is dictated by whether the next node is > or < the requested key. Since a key can exist at multiple levels, however, it is also important that removing it will remove it everywhere by finding the predecessor for that node and pointing it to its successor. For insertion, we similarly find predecessor and point it to the new key, then point the new key to the predecessor's former successor. By merely traversing levels and making updates on all levels as needed, this preserves the order and representation so that traversal remains consistently quick.

4. Let n be the number of stored keys and let p = 1/2. State the expected running time of search, insert, delete, predecessor, and successor. Give a short probabilistic explanation based on geometric promotion and the expected O(log n) number of levels.
When p = 1/2, the expected runtime for each of those operations is O(log n). Since Pr[promotion] = 1/2, each insertion is only 50% likely to be promoted to a higher level. With randomization determining how many times a key will be promoted, this means that there will be about log n levels on a skip list, with less keys on higher levels and the full sorted list at level 0. This resulting log n levels means that searching can be done more quickly, as searching higher levels and only moving lower as needed can eliminate the need to search large portions of the list. This searching process is present in insertion, deletion, contains, and predecessor/successor operations, so each only needs O(log n) to run.

5. State the worst-case running time of one operation and explain why randomization does not eliminate that worst case. Distinguish expected analysis from a worst-case guarantee.
The worst case would involve traversing the entire list spread across many levels: O(n + L), where L = max_level. This would be rare, but thanks to randomization there is a chance that all insertions get promoted to the highest level, requiring full traversal across all levels for a key that isn't present in the list. Rather than eliminating this worst case, randomization allows for the possibility of that to happen, however slim. Thankfully, this potential worst-case is not a guarantee because randomization also creates a much greater chance for only around half of the keys to be promoted per level, which will make it way more likely that we'll achieve O(log n) rather than O(n + L) for any given skip list

6. State the expected additional space as a function of n and explain why each key has expected constant height. Also state the role of max_level in the implementation.
The expected additional space is O(n) where n is the number of total keys in the list, since we are potentially storing each single key on multiple levels. Each key has constant height thanks to the limit implemented by the max_level cap, which dictates how many levels are allowed for a skip list. This max_level will ensure that the key's promotion level can't exceed the constant size, though it can result in issues for really large n sets because all levels are likelier to have more keys and it's therefore not likely to achieve O(log n)

7. Discuss when a skip list is useful. Include at least two tradeoffs or limitations compared with a balanced binary search tree, such as probabilistic performance, pointer overhead, cache behavior, or reproducibility.
A skip list is useful in several scenarios, such as when you want to maintain an ordered linked list that can also handle insertion/deletion in the middle without all of the rebalancing or restructuring other data structures may require. It is also pretty simple in its implementation compared to other data structures, included the balanced BST, though maintaining pointers can introduce some additional overhead. Skip lists are interesting in that they give expected O(log n) complexity for operations, because the randomization will mean that it is not exact. Balanced BSTs are instead worst-case O(log n). Skip trees are also slightly inconsistent, since the randomization of promotion will result in a different skip tree each time. This results in reproducibility issues that a BST doesn't have, because a balanced BST will handle data the same way each time.
